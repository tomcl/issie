## Introduction

Security has gotten increasingly tighter on macOS Sequoia, which had resulted in un-signed `.dmg` files generated by `electron-builder` not being able to be opened except through zsh. We therefore need to a) code-sign our binaries and b) notarize our `.dmg` files, in order for macOS to not treat ISSIE like malware.

We note here that code-signing the binary _only_ will result in the need to go into "System Preferences" > "Privacy & Security"> "Security" > "Open Anyway". While _both_ code-signing and notarizing will allow people with "System Preferences" > "Privacy & Security"> "Security" > "Allow apps from App Store and Known Developers" set to open the application without much harrassment.

Follow the sections below step-by-step to code-sign and notarize with the current ISSIE build system.

## Everything You Need (From Apple's Website)

To start the code-sign and notarize process we need three things:

1. Developer ID Application Certificate,
2. Provisioning Profile, and
3. Application-specific Password For `notarytool`.

**Developer ID Application Certificate:**

1. Go to [developer.apple.com](developer.apple.com) and sign in.
2. Go to "Certificates, Identifiers & Profiles" > "Certificates" or use [this link](https://developer.apple.com/account/resources/certificates/list).
3. Make a new certificate by clicking the "+" button.
4. Choose "Developer ID Application" and "Continue".
5. Provide your Certificate Signing Request file, obtain that through [these steps](https://developer.apple.com/help/account/create-certificates/create-a-certificate-signing-request/) on your Keychain Access app on your Mac. "Continue" .
6. Click "Download" to obtain your certificate.
7. Double-click your certificate file to install to Keychain Access app.
8. In the Keychain Access app, go to "System" > "Developer ID Application: xxxxx (xxxxxx)", and double-click to see your certificate.
9. Retrieve and save: "Subject Name" > "Organization Unit" (this is `<your-team-id>` later), "Fingerprints" > "SHA-1" (this is `<your-certificate-sha-1>` later).

**Provisioning Profile:**

1. Go to [developer.apple.com](developer.apple.com) and sign in.
2. Go to "Certificates, Identifiers & Profiles" > "Profiles" or use [this link](https://developer.apple.com/account/resources/profiles/list).
3. Make a new profile by clicking the "+" button.
4. Choose "Developer ID" and "Continue".
5. Select an App ID, if you don't have one the form will direct you to create one, or follow [these steps](https://developer.apple.com/help/account/manage-identifiers/register-an-app-id/). Basically fill in any "Description" and "Bundle ID" will alow you to create the App ID. "Continue".
6. Choose the previous certificate that you created and "Continue".
7. Give the system a "Provisioning Profile Name" like issie, and "Generate".
8. Click "Download" to download your provisioning profile.
9. (I do not remember needing to install it, even though the system recommends you to.)
10. Copy the provisioning profile to the ISSIE directory and note its name (this is `<path-or-name-of-your-provisioning-profile>` later).

**Application-Specific Password:**

1. Go to [id.apple.com](id.apple.com) and sign in.
2. Go to "Sign-In & Security" > "App-Specific Passwords".
3. Click the "+" button or the "Generate a App-Specific Password" button to create a password.
4. Enter `notarytool` in the textbox, and give your normal Apple ID password.
5. Save your App-Specific Password, as this will not be shown again (this is your `<your-notarytool-password>` later).

## Signing and Notarize with `electron-builder`

The signing and notarizing is built into `electron-builder`, we just need to provide it with the relevant information. Note that signing has always been done by `electron-builder` whereas previously notarizing was done with `scripts/afterSignHook.js` which is currently broken. To sign and notarize:

1. Add your provisioning profile file at the root of the repo.
2. Replace the `mac` and `dmg` sections in `package.json` with the following:

    ```json
    "mac": {
        "category": "public.app-category.productivity",
        "entitlements": "public/entitlements.mac.plist",
        "entitlementsInherit": "./public/entitlements.mac.plist",
        "icon": "public/icon.icns",
        "target": [
        {
            "target": "dmg",
            "arch": "x64"
        }, {
            "target": "dmg",
            "arch": "arm64"
        }
        ],
        "hardenedRuntime": true,
        "identity": "<your-certificate-sha-1>", // replace this
        "provisioningProfile": "<path-to-provisioning-profile>", // replace this
        "notarize": true
    },
    "dmg": {
        "icon": false
    }
    ```

3. Set your credentials in your environment with the following script (or alternatively see what to supply [here](https://www.electron.build/app-builder-lib.interface.macconfiguration#notarize)):

    ```sh
    export APPLE_ID="<your-apple-id>"
    export APPLE_APP_SPECIFIC_PASSWORD="<your-notarytool-password>"
    export APPLE_TEAM_ID="<your-team-id>"
    ```

Run `npm run dist` will give you the ready to distribute `.dmg` file.

## Manually Notarize (Not Recommended)

Apple's `notarytool` server sometimes experiences performance issues, which would result in very long build times, as `electron-builder` just waits for Apple's server to come back with a response. In this case, we use command line tools to submit the disk image to Apple, and then check back at intervals. Use the following commands:

1. To submit a `.dmg`:

    > Remember to keep the returned submission id. You need this later to check the status of your submission.

    ```sh
    xcrun notarytool submit ---apple-id "<your-apple-id>" --team-id "<your-team-id>" --password "<your-notarytool-password>" <path-to-your-dmg-file>
    ```

2. To check the status of your submission:

    ```sh
    xcrun notarytool info --apple-id "<your-apple-id>" --team-id "<your-team-id>" --password "<your-notarytool-password>" <your-submission-id>
    ```

3. To retrieve the run log of `notarytool` to see why it is not accepted:

    > Please note that if your submission is in progress, no run log will be retrieved. System will instead show some error saying your submission id does not exist.

    ```sh
    xcrun notarytool log --apple-id "<your-apple-id>" --team-id "<your-team-id>" --password "<your-notarytool-password>" <your-submission-id>
    ```

If the `notarytool info` command returns accepted: you are ready to distribute your `.dmg` file!
