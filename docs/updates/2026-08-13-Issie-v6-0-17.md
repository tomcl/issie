# ISSIE v6.0.17

This summer the focus was primarily on quality. We have been able to close very many long-standing user-interface rough edges:

- weird fixed rhs unusable scrollbar has gone
- we have bespoke dialogs for open and new projects - instead of surprising not-quite-right electron built-in dialogs
- components can be drag-and-dropped from catalog as is expected and nice
- custom component resize & port movement is materialised from right-click menu items, rather than via an unexpected ctrl-key-drag binding
- all keys are now harmonised with expected platform usage
- we have a proper splash-screen on startup
- weird electron menus are no longer used and that menu bar disappears - needed items on them are now integrated properly on nav bar menus
   - the electron menu bar reappears in dev mode only, with a *developer* menu.
- the sheet hierarchy trees in menus now look like proper trees - this is a big improvement over the tree-organised blobs we had before.

We have significant new features in two areas; performance and scalability.

## Performance

Perhaps the most surprising new feature is an **11 times speed increase** in the simulator, which also now handles memories properly, so the memory and time costs of tracking a RAM updated over a long simulation is close to the theoretical minimum. This was not originally planned, but a serendipitous side effect of reviewing and cleaning up the simulator code for better readability. More improvements will require aggressive algorithmic optimisations and direct code generation. For the future!

## Scalability

We have finally managed to add **properties** (AKA parameters) to Issie sheets. With that, we have implemented a library mechnaism nicely integrated into the catalogue. Now, anyone can design a library component as a design sheet, or even a whole hierarchical design, which can be used identically to a normal built-in components. When so used the component implemntation is hidden. We have added an affordance so users can temporarily reveal it in a read-only form to make library components less opaque.

The property mechanism was innovated by HLP students last year and went through four prototype iterations before what we now have. It was challenging to find something that did not clutter up the normal user interface - if you are not using it you don't notice it - but allows proper use of hierarchical properties.

## Bug Fixes

The quality work included closing the long backlog of issues. A few of these detailed bugs we fixed not found by the other quality work.

Hard work with agentic AI has helped to close quite a number of bugs we never knew we had - mostly corner cases in > 32 bit implementations. Since the normal Issie use is all < 32 bits this was not much tested.

We have also found a few genuine nasty UI crashes - we hope as result of this that in 2026-7 Issie will be 100% stable.
